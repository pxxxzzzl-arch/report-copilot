## 2. 字段

每行一道题：

```json
{"id": "q001", "type": "table_number",
 "question": "贵州茅台2024年研发投入合计是多少？",
 "answer": "695,376,735.81元（约6.95亿元）",
 "gold": [{"doc_id": "600519_2024", "page": 11, "span": "695,376,735.81",
           "alt": [{"doc_id": "600519_2024", "page": 119}, {"doc_id": "600519_2025", "page": 118}]}],
 "note": "研发投入情况表-研发投入合计"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `q` + 3 位数字，唯一 |
| `type` | 是 | `fact` / `table_number` / `multi_hop` / `calc` / `compare` / `out_of_scope` |
| `question` | 是 | 问题原文 |
| `answer` | 是 | 参考答案（生成评测用）；数值带单位，大数附"约 X 亿元"便于核对 |
| `gold` | 是 | 证据列表。**每条是一份必需的证据**，Recall 按条计算；`out_of_scope` 题为空列表 |
| `gold[].doc_id` / `page` / `span` | 是 | 主位置：文档、PDF 物理页码（从 1 开始）、答案关键片段（照抄原文） |
| `gold[].alt` | 否 | 与主位置**等价**的其他位置（同一 span），命中其中任意一个即算命中这条证据 |
| `note` | 否 | 出处说明、口径陷阱等 |

## 3. 命中判定

召回的 chunk 命中某条 gold，当且仅当存在该 gold 的某个位置（主位置或任一 alt）满足：

1. `doc_id` 相同；
2. 该位置的 `page` 落在 chunk 的 `[page_start, page_end]` 内；
3. `normalize(chunk.text)` 包含 `normalize(span)`。

`normalize` 统一使用 `common/text.py`：全角转半角，再去掉所有空白。

## 4. 标注规范

### 4.1 span
- 取**单个表格单元格或单个句子内**的原文片段，**不跨单元格**。例如取 `695,376,735.81`，不取 `研发投入合计695,376,735.81`。
  原因：解析器可能在单元格之间插入分隔符，跨单元格的片段就无法再连续匹配。
- 数字照抄原文，保留千分位逗号和小数位。
- 尽量不少于 4 个字符。短 span（如两个字的人名）靠页码约束来避免误命中，校验脚本会给出警告。
- 如果短 span 在标注页上会成为其他文字的子串（如 `2.30` 在同页的 `-92.30` 中），就换一个问法（见 q035）。

### 4.2 alt（等价位置）
收录条件：**在该位置，同一主体、同一期间、同一指标标签下出现同一个 span**，也就是只看这一页就能回答这道题。

| 收录 | 不收录 |
|---|---|
| 主要会计数据表、合并报表、附注、补充资料中标签相同的同一数字 | 标签不同的同值数字：研发费用 ≠ 研发投入，技术人员 ≠ 研发人员 |
| 下一年年报"上年同期"列中标签相同的数字 | 同值但属于其他主体：控股股东的法定代表人 |
| 研发支出附注中的"合计（其中：费用化研发支出…）" | 属于其他期间的事实：下一年年报里的审计机构、审计意见 |
| 本年度财务报表审计机构：其他有关资料 / 聘任情况 / 审计报告 / 审计报告签章 | 内控审计、验资、募集资金核查中提到的同名事务所 |
| | 作为子串出现在其他数字、所有者权益变动表等无明确标签的位置 |

- 同一数值换了单位写法时，span 无法匹配，不会被收录，这类位置会被判为"未命中"（见第 6 节）。例如比亚迪合并利润表和附注以千元列示，净利润写作 `32,619,022`，主要会计数据表写作 `32,619,022,000.00`。
- 校验脚本对"span 在同文档其他页出现、但未列入 alt"只给 warning。v1 里这类 warning 共 25 条，都是**审查后有意不收录**的（研发费用、技术人员、内控审计、无关子串等），属于正常情况；另有 1 条是"span 过短"（q018 `陈华`）。

### 4.3 题型要求
| 题型 | 要求 |
|---|---|
| `table_number` | 答案是表格里的单个数值 |
| `fact` | 答案是文字事实（人名、机构、方案等） |
| `multi_hop` | 至少 2 条 gold，分布在不同页或不同文档 |
| `calc` | 至少 2 条 gold（计算的输入数字）；**答案不能在原文中直接查到**；`answer` 里写出算式 |
| `compare` | 至少 2 条 gold，来自至少 2 份文档（跨公司或跨年度） |
| `out_of_scope` | gold 为空；**出题前要全文检索关键词，确认年报确实没有披露**，并把检索结论写进 `note` |

## 5. v1 构成与制作过程

- **题型分布**：table_number 16、fact 12、multi_hop 8、calc 8、compare 8、out_of_scope 8。
- **覆盖**：12 份年报每份至少被 3 题引用。
- **刻意设置的陷阱**：
  - 单位：宁德时代、中芯国际以千元列示（q047、q052）；
  - 口径：营业收入 vs 营业总收入（q037）；
  - 重述数据：比亚迪送转股后，每股收益被重述（q030）；
  - 代理职务：华涛（代）（q027）。
- **制作流程**：
  1. 起草：在原文中检索，按证据出题；
  2. 机器校验：`validate_goldset.py`，每个 span 都在标注页上找到，0 error；
  3. 逐条审查 alt：约 250 个 span 出现位置逐一查看上下文，决定是否收录；
  4. 第二遍复核：用 Decimal 重算全部 calc 题；把 out_of_scope 的关键词再全文检索一遍；通读全部题目。
- **复核中修正的问题**：
  - q023 的备注错误（茅台 2024 年报已由天职国际改聘为天健）；
  - q039、q044 原本问的比例在年报中直接披露，不算计算题，换成了年报未直接给出的指标；
  - q038 的中间结果（967.07 → 967.06 千元）；
  - 5 个跨单元格的 span；
  - 默认规则误收的 alt（q035）。

## 6. 已知问题与局限（v2 候选）

1. **起草和审核都由 AI 完成**，没有真正独立的人工审核。机器校验保证"证据确实在原文里"，但"问法是否合理、答案是否完整"建议人工抽查。优先抽查：
   q016、q023、q027、q030、q032、q035、q037、q040、q047、q058。
2. **研发支出附注被收录为"研发投入"的等价位置**（q001、q002、q010、q016、q031、q033、q034、q046 等）。
   茅台、五粮液、中芯国际、宁德时代的研发支出合计与研发投入相等；但泸州老窖 2024 年两者不等（260,975,311.10 vs 280,166,160.16）。这个口径是否合适，需要人工确认。
3. **同值不同单位写法的位置没有收录进 alt**。例如比亚迪 2025 年报第 126、208、216 页以千元列示的净利润 `32,619,022`，q012 召回这些页会被判为未命中，Recall 可能略微偏低。
4. **拒答题只覆盖 4 类**：投资建议 / 预测、语料外公司、年报未披露、实时行情。"问题前提错误"之类的题目还没有覆盖。
